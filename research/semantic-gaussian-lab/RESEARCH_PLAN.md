# 具体研究方案：预算约束下的增量式全景 Gaussian 地图

## 1. 把研究问题收紧

在连续 RGB-D 观测下，维护可渲染的三维 Gaussian 地图及跨视角一致的语义/物品实例；在同样的显存上限与单帧时间预算下，比较地图覆盖、旧区域渲染质量、实例一致性之间的权衡。

“Gaussian + 语义”已有研究先例，例如 [SGS-SLAM](https://github.com/ShuhongLL/SGS-SLAM)；稳定/不稳定点的在线优化可参考 [RTG-SLAM](https://github.com/MisEty/RTG-SLAM)。本课题的候选贡献应是**预算调度与物品级长期保留策略**，需要实验验证，暂不声称新颖算法或性能优势。

第一阶段使用已知位姿，把定位误差和地图遗忘分开；第二阶段接入相机跟踪，才讨论完整 SLAM。优先 RGB-D：深度和尺度可直接约束几何。RGB-only 作为后续输入适配层，需额外验证深度尺度、漂移、位姿和分割误差，不与 RGB-D 结果混报。

## 2. 数据流和模块

```text
RGB / depth / K / timestamp
        ↓
PoseProvider（阶段一读取输入位姿，阶段二 RGB-D tracking + loop closure）
        ↓
PanopticProvider（Mask2Former；类别 + 实例 mask + confidence）
        ↓
depth 反投影 + 局部遮挡过滤 + 3D instance association
        ↓
Gaussian 插入 / 证据融合 / stable-active 调度 / 删除或归档
        ↓
局部 gsplat 优化 + 旧关键帧 replay
        ↓
同步 RGB 视频、3D 外观/语义/实例、相机轨迹、实测开销
```

模块输入统一为 `Frame`，不绑死某个分割模型或数据集。v0.1 支持通用 manifest 与 TUM 导入。Replica/ScanNet 需另写适配器，尤其要核对标签表、深度单位、坐标系和数据许可。

## 3. 三维地图表示

目标版每 Gaussian 保存位置 μ、旋转四元数 q、三轴尺度 s、不透明度 α、颜色/球谐系数、语义证据、全局实例 ID、观测次数、最近可见时间、所属子地图。

v0.1 已实现各向同性尺度、RGB/DC 球谐导出、语义证据、实例 ID 和观测元数据；高频球谐与各向异性参数留到 GPU 验证后。

语义是“这是什么类别”，实例是“这是哪一件物品”。墙/地板等 stuff 只需类别；椅子等 thing 同时携带实例 ID。不要把二维 mask 编号直接当长期物品 ID。当前关联使用同类别的世界体素重叠和中心距离，一帧内一对一。后续结合可见面覆盖、重投影 mask IoU、外观特征和空间邻接做 Hungarian 匹配；物体合并/拆分要有显式状态和别名，防止永久重复 ID。

语义证据融合：对可信观测累积类别证据，再归一化；低置信度像素保持 unknown。冻结可防止旧区域变差，也会锁定早期分割错误；目标版需要“高置信度多帧冲突时重开局部优化”的机制。

## 4. 地图更新与资源控制

1. **新区域插入：**以体素覆盖为第一版条件，之后增加 rendered silhouette、颜色与深度残差。只在满足可见性与深度一致性时融合，避免穿墙和遮挡污染。
2. **活动集合：**当前视锥、最近 K 个关键帧和误差较大/尚未稳定的点；旧稳定区固定。Colab 初始参数建议每 5 帧优化 5 步，活动点最多 6,000；先测性能，再调参。
3. **时间预算：**预处理、tracking、segmentation、mapping、render、传输分别记录。v0.1 只为 CPU 融合设软截止，分割预计算；最终采用有界异步队列和过期结果处理，语义结果延迟时几何可先行，不能将缓存推理时间隐藏。
4. **显存预算：**先用 Gaussian 数量硬上限限制地图参数；进一步按实际 `torch.cuda.memory_allocated/max_memory_allocated` 调整活动集合、分辨率和迭代数。还必须计入模型权重、特征图、optimizer state 和 rasterizer 临时 buffer。
5. **旧区域保留：**固定早期关键帧 + 有界分层关键帧库；每次优化轮换 replay。预算不足优先合并冗余点和归档冷子地图，再删除低支持离群点。v0.1 达上限会拒绝新点，可能停止扩展；子地图换入换出尚未实现。
6. **物品优先级假设：**在同样总容量下，为小物体、实例边界和稀有类别保留一定配额，减少大面积墙/地板挤掉小物品。这个策略是后续研究变量，尚未实现，需用消融验证。

当前局部优化目标为：

`L = L_RGB + 0.15 L_depth + 0.03 L_semantic`

旧帧 replay 通过选帧加入同一目标；尺度、不透明度、颜色、位置和语义 logits 只对活动点求解。位置约束在原体素内部，防止优化后哈希索引失效。最终应增加边界/几何正则、鲁棒深度损失与可见性权重。物品 ID 为离散关联结果，不直接通过该损失学习。

## 5. 数据与实验

| 阶段 | 数据 | 目的 | 输入约束 |
|---|---|---|---|
| 管线验证 | 内置合成室内闭环 | 硬上限、参数冻结、跨帧 ID、可视化 | 位姿/深度/分割真值，不能评估学习分割精度 |
| 真实数据调试 | TUM RGB-D xyz/desk | 尺度、时间戳、RGB-D 接入、模型推理 | 已知位姿，缺乏完整三维语义实例真值 |
| 几何与旧区质量 | Replica 长轨迹/回访 | 新视角质量、旧区域随时间的变化 | 统一 train/test 视角，不能用训练帧代替 novel view |
| 语义/物品 | 有授权的 ScanNet 等 | 3D mIoU、AP/PQ、ID 切换 | 必须明确官方标注、划分和 label mapping |
| 实际演示 | 手机 RGB-D / 带轨迹的 RGB-D 相机 | 同步视频与地图扩展 | 再单独评测 tracking 与 dynamic handling |

至少比较以下配置：无限预算或高预算参考、纯几何融合、带语义但无稳定区保护、稳定区冻结、有 replay、预算调度、物品配额。每组使用同样输入/分割缓存/分辨率/随机种子，独立进程测内存，重复运行报告方差。

核心指标：

- 几何：深度 MAE、准确率/完整率或 Chamfer，必须同时报告覆盖率。
- 外观：固定 held-out 视角的完整渲染 PSNR/SSIM，必要时 LPIPS。
- 旧区：固定旧测试视角，每隔一段时间重渲染；计算相对上一个检查点的退化曲线，使用相同可见/有效像素掩码。
- 语义：2D/3D mIoU；实例：3D AP/PQ、同物体 ID 切换率、重复实例数。
- 开销：每阶段耗时 p50/p95、端到端更新延迟、丢帧/延后帧、GPU peak、CPU RSS、Gaussian 数量、关键帧数、磁盘增长。
- 加入 tracking 后才报告 ATE/RPE；使用真值位姿时不能报告“定位精度”。

v0.1 的旧视角 probe 是点中心投影诊断，不能替代上述渲染质量指标；目前测试证明工程不变量，尚未验证研究假设。

## 6. 可执行里程碑

| 里程碑 | 交付物 | 验收条件 |
|---|---|---|
| M0 已完成本地验证 | CPU 原型、同步查看器、合成序列、测试 | 连续播放、地图增长、语义/实例切换、实测时间、硬容量约束 |
| M1 Colab 验证 | notebook、真实 TUM 适配、Mask2Former、gsplat 接口 | 单 Gaussian 梯度检查与小序列运行成功；保存环境和峰值显存；修复兼容问题 |
| M2 真实语义地图 | 更长 RGB-D 序列、稳定物品 ID | 真值或人工核验物品，遮挡/回访时检查 ID，排除标签配色伪效果 |
| M3 预算与保留实验 | 统一基准、消融、旧区曲线 | 同预算对照，明确覆盖/质量/时延权衡，证明或否定物品配额假设 |
| M4 完整演示 | tracking + 回环 + 异步分割 + 可复现视频 | 输入视频和地图时间戳一致，显示分割延迟和端到端开销 |

M1 代码已经提供，但需要在 Colab 中执行。Colab 的 GPU 型号、可用额度和运行时长不固定；实验先使用小序列，成功后再扩展。默认建议以 T4 可承受的规模起步，性能目标必须在实际设备上测量。

## 7. 最终演示布局

左侧：RGB 视频，可叠加语义或实例 mask。右侧：随时间扩展的 Gaussian 地图，可切换外观/语义/实例、选中一件物品，并显示相机轨迹。底部：Gaussian 数量、当前/峰值显存、分阶段耗时、端到端延迟、旧区域质量检查点。演示要标明使用输入位姿还是在线跟踪，以及分割是缓存还是在线推理。
