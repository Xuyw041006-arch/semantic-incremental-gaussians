# 实验与验证记录

## Colab T4 真实 RGB-D 实验：已完成

2026-10-07 实际执行。数据为 TUM RGB-D `freiburg1_desk`，320×240，119 帧、约 20 秒；99 帧建图，20 帧留出，不参与融合或优化。相机位姿来自数据集 groundtruth。

[已执行的 Colab notebook](https://colab.research.google.com/drive/1pJRfsBYrjzoTGzjTftAHG2kXYamMAEcx)。环境为 Tesla T4 / Python 3.13.15 / PyTorch 2.11.0+cu130 / CUDA 13.0，完整依赖版本已保存。

方法：4 cm 体素融合、每帧最多 4,500 个样本、稳定阈值 5 次观测；CUDA 每五帧优化一次，每次五步，活动 Gaussian 上限 6,000，联合 RGB/深度/语义损失并回放早期关键帧。Mask2Former COCO 全景分割产生真实预测；语义概率存到 Gaussian，帧内实例通过三维体素关联为跨帧 ID。Gaussian 为各向同性、常量 RGB，尚不是完整 SLAM。

固定采样对照关闭自适应预算。四组计时均不保存地图快照，回放另跑一次。小容量和 24k 冻结组经过独立复核，最终结果无并行验证任务干扰。每组仅一条短序列和一次计时结果，未做多种子统计。

| 配置 | Gaussian 数 | 更新 p50 / p95 ms | 优化峰值显存 MiB | 留出 PSNR dB | SSIM | 覆盖率 |
|---|---:|---:|---:|---:|---:|---:|
| 仅融合 24k | 22,789 | 28.58 / 51.56 | 0.00 | 13.983 | 0.328 | 99.43% |
| CUDA 6k，冻结 | 5,903 | 23.52 / 150.74 | 310.58 | 11.607 | 0.226 | 91.33% |
| CUDA 24k，冻结 | 22,789 | 33.73 / 182.15 | 353.98 | 14.213 | 0.343 | 99.42% |
| CUDA 24k，不冻结 | 22,789 | 44.00 / 204.33 | 354.12 | 14.823 | 0.392 | 99.43% |

Mask2Former 前向与后处理 p50 / p95：**64.95 / 83.10 ms**；不含图像预处理、传输和模型加载。分割预计算，未计入地图更新，不能宣称端到端实时。

更新耗时为融合/关联加 CUDA 优化，不含读取、评估、序列化与网页渲染。每五帧优化一次，中位数会掩盖尖峰。显存为 `torch.cuda.max_memory_allocated` 张量峰值，不含分割模型进程、驱动上下文和缓存保留量；仅融合组的 0 表示不执行优化，评估仍使用 CUDA。24k 地图数组容量为 13.37 MiB，进程峰值 RSS 约 1.35 GiB，Gaussian 上限并不是系统总 RAM/VRAM 上限。

质量使用 gsplat 完整 RGB+期望深度渲染，在 0.15–8 m 的有效深度区域排除预测人物后计算。无覆盖像素保留黑色并计入误差，覆盖率另以 alpha>0.1 统计；SSIM 为完整 SSIM 图在该区域的均值。

### 实验发现与限制

- 6k 容量更省内存，但覆盖率从 99.42% 降到 91.33%，PSNR 从 14.213 降到 11.607 dB；拒绝了 71,876 次观测。数量上限控制了增长，同时损失新区域。
- 24k CUDA 相比仅融合提高约 0.23 dB。当前画面仍明显模糊并有浮点状伪影，Gaussian 表达和优化量不足。
- 不冻结组 PSNR 为 14.823 dB，CPU 更新中位耗时也更高。本轮不能证明冻结是质量最优策略。
- 固定旧留出视角 3：24k 冻结组在第 20/99 个建图帧的 PSNR 为 14.163/11.181 dB，下降 **2.98 dB**；6k 组下降约 6.71 dB。冻结参数仍无法阻止新增几何遮挡、投影误差和稀疏表达影响旧区域整体质量。“旧质量受控”尚未解决。
- 最终 50 个轨迹 ID 包含明显碎片化，不能当作 50 件真实物品。TUM 此序列没有语义/实例真值，因此没有报告 mIoU、PQ 或跟踪准确率。

### 下一轮优先实现

1. 各向异性尺度/旋转、梯度驱动增密、深度残差与遮挡剔除，以及更多优化步数；在相同留出集合验证画质和成本。
2. 通过固定旧视角验证子地图，退化时局部解冻修复，再实施子地图换入/换出；将旧视角 PSNR 降幅设为显式约束。
3. 加入物品级特征、跨视角一致性和实例合并；用带标注的 Replica/ScanNet 评估三维语义/实例精度，保留 TUM 真实传感器测试。
4. 异步分割和关键帧调度，将整个输入到地图的流程计入端到端 p95；再接入位姿估计与回环。
5. 多房间和回访序列、多容量档位、至少三次独立计时，形成正式结论。当前为工程基线。

## 固定采样的 CPU 对照

每组独立进程、100 帧、固定种子。这里只运行了一次，数值会受设备负载影响。更新时间为 CPU 融合及关联，不包括图像生成、编码、传输、渲染和分割模型。

| 配置 | 最终 Gaussian 数 | 数组容量 MiB | 更新 p50 ms | 更新 p95 ms | 进程峰值 RSS MiB |
|---|---:|---:|---:|---:|---:|
| 上限 8,000，冻结 | 8,000 | 0.610 | 4.699 | 15.377 | 65.34 |
| 上限 24,000，冻结 | 20,396 | 1.831 | 8.779 | 15.697 | 66.28 |
| 上限 50,000，冻结 | 20,396 | 3.815 | 8.814 | 15.305 | 65.08 |
| 上限 24,000，不冻结 | 20,396 | 1.831 | 15.982 | 17.508 | 66.11 |

8,000 上限组拒绝了 113,774 次新增观测。其较低后期耗时伴随着地图停止扩展；不能由此认定它更好。24,000/50,000 组地图相同，因为本序列最终没有达到这两个上限。预分配 NumPy 数组存在惰性页面分配，RSS 不一定按容量同比增加。

原始数据见 `results/ablations/comparison.json` 和各组 `metrics.json`。这组结果仅验证工程行为，不构成真实场景质量、模型精度或论文结论。
